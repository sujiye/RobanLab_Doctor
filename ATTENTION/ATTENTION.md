# ATTENTION —— Roban Agent 强制安全规则

> 本文件是最高优先级的安全约束。每次执行任何机器人操作之前，必须先完整读取本文件；
> 如果本文件缺失、为空或无法读取，禁止执行任何操作。
>
> 本文件与其它 skill、知识库、历史经验、报告或用户之前的习惯冲突时，以本文件为准。
> 只有用户在当前对话中明确修改本文件，才能改变这些规则。

## 规则 1：知识库不得记录或使用机器人 IP

- 任何知识库内容都不得写入机器人 IP：包括 `kb/cases/*.json`、`kb/events.jsonl`、
  自动习得的案例、学习笔记、故障签名、证据快照和备注。
- 读取知识库时，不得采用其中的 IP、主机名或连接地址。知识库只能提供“故障签名 → 修复剧本”经验。
- 当前机器人 IP 必须来自用户在当前对话中的明确输入；用户没给就询问，不能猜、不能扫描、
  不能从历史会话、报告、日志或知识库中取。
- 如果发现知识库条目里出现 IP，忽略该条目中的连接信息，并在报告中标记“知识库含 IP，已忽略”；
  不要用这个 IP 去连接机器人。
- 写入知识库前必须做 IP 脱敏；IPv4 地址统一替换为 `[REDACTED_IP]`。

## 规则 2：所有可能让机器人运动的指令，必须先询问用户

- “可能让机器人运动”的指令包括但不限于：关节目标位置/速度/力矩、头部运动、步态/行走、
  底盘移动、遥控、零位标定、上电/卸力、任何会让关节或整机产生位移、转动或姿态变化的操作。
- 执行前必须向用户说明：
  1. 要动哪个关节/部位；
  2. 目标角度或范围、速度、持续时间；
  3. 预期会看到什么运动；
  4. 可能的碰撞、失稳、跌落风险；
  5. 如何立刻停止。
- 必须得到用户明确的“确认/执行/同意”后才能运行。沉默、含糊、默认、上次同意过，都不算批准。
- 批准是逐次有效的：动作、参数、机器人状态或故障发生变化时，必须重新询问。
- 默认先 dry-run；没有批准不得加 `--confirm`、不得直接发布运动指令。

## 规则 3：不得自行重启机器人或让关节断电

- 禁止自行执行：机器人重启/关机、`reboot`/`shutdown`、`killall roslaunch`、
  `rosnode kill`/`pkill` 关键节点、重启 `roscore`/BodyHub、固件升级、断电、拔线。
- 禁止自行让关节断电或改变扭矩：`SetServoLockState*` 的 0/卸力、`Torque_Enable=0`、
  直接写舵机寄存器、`SyncWrite*`、`InstWrite*`、`SetServoTarPosition*`。
- 这些操作可能导致机器人摔倒、关节失稳或后续动作全部失效。即便用户口头同意，
  本 agent 也不自行执行；只能建议用户手动操作，并说明支撑条件、风险和复检方法。
- 允许的例外只有白名单内的非运动节点重启（当前为 `restart-chin-camera`），
  且必须经过 `--confirm` 和前置条件检查；它不是“机器人重启”，也不触碰关节电源。

## 规则 4：所有指令必须显式、可立即停止

- 禁止隐式批处理、无限循环、后台常驻运动、`nohup`/`&` 启动运动、把多条运动指令排队后自动执行。
- 运动指令必须在前台或带超时/看门狗的受控进程中执行，用户必须能按 Ctrl-C 终止。
- 开始任何可能让机器人运动的指令之前，必须先把“如何立刻停止”告诉用户，至少包括：
  1. 按下机器人硬件急停或直接切断机器人电源（最可靠，优先）；
  2. 在发起命令的终端按 Ctrl-C，终止当前前台进程；
  3. 不要以关闭网页、关闭 dsh、断开 SSH 作为停止手段——断连不等于停止，
     机器人端可能继续执行已经排队的指令；
  4. 如果已经产生运动队列，只能使用现场验证过的停止方式；未验证前不要继续下发新指令。
- 如果无法给出确定的停止方式，或者现场没有人能执行急停，禁止开始运动。
- 每条命令都必须是显式的：日志里能看出完整命令、目标、参数和发起时间。

## 执行前检查清单（每次必须走）

1. 读取本文件，记录路径、时间和 SHA-256。
2. 确认机器人 IP 来自用户当前消息；知识库/历史记录中的 IP 一律不用。
3. 把本次要执行的每个动作分类为：只读 / 非运动修复 / 运动 / 禁止。
4. 如果有运动动作：先取得用户逐次批准，并给出上面第 4 条要求的停止方式。
5. 如果有禁止动作：停止，只输出人工建议，不执行。
6. 如果要读写知识库：写入前脱敏 IP；读取时忽略任何 IP/主机字段。
7. 任何一项无法满足：停止执行，向用户说明原因。

## 零位标定工作流的边界

零位偏移无法只靠软件读出；手机相机只能作为人工测量的辅助记录，不能替代现场确认。允许的自动化范围是：

- 读取现有 `offset.yaml` / `dxlInitPose.yaml`；
- 根据人工测得的实际角度计算候选偏移；
- 在本地生成补丁文件、备份文件和 apply 脚本；
- 读取修改后的 offset 做比对和复检。

仍然禁止自动执行：

- 直接写机器人上的 `offset.yaml`、`dxlInitPose.yaml` 或舵机 EEPROM；
- 自动重启 BodyHub / roslaunch / 机器人；
- 自动让关节上电、卸力或运动；
- 在没有人工支撑、没有逐次批准、没有“立即停止方式”的情况下做任何运动。

apply 脚本必须由用户手动在机器人上运行；重启 BodyHub 也必须由用户手动完成。
手机相机测量结果必须让用户看到并确认，不能把自动识别结果直接当成物理真值。

### 允许的“控制读”例外

为了识别用户手动转动后的关节，允许在以下条件全部满足时做一次短暂的控制读：

- 机器人已支撑，处于 `preReady`，`masterID=0`；
- 用户逐次明确批准这次控制读；
- 只执行 `StateJump <id> setStatus` → `StateJump <id> reset`，然后读取 `GetJointAngle`；
- 脚本必须用 `trap` 确保退出时 `reset`，并在结束后检查 `masterID=0`、状态回到 `preReady`；
- 不发布运动指令、不改扭矩、不写 offset、不重启任何节点。

控制读失败或无法释放状态机时，立即停止并报告，不得继续标定。

## 视觉/自然语言诊断的边界

- 用户描述和图片是证据，不是物理真值；必须与只读 probe/selfcheck、日志和现场确认交叉验证。
- 不能仅凭图片断言“电机坏了、编码器坏了、扭矩异常”；只能描述可见事实（姿态、线缆、接头、LED、屏幕、损伤）和不确定性。
- 图片角度、遮挡、光照、分辨率不足时，必须写明“无法判断”，不能补造。
- 出现冒烟、焦味、过热、火花、跌落时，先让用户停止并人工断电检查，禁止继续诊断或运行。
- 视觉诊断只读；白名单动作（当前 `restart-chin-camera`）也必须用户确认后才执行。
- 不得由视觉诊断流程直接触发运动、重启、上电/卸力、零位写入。

## 违规处理

- 发现违规动作、缺失批准、缺失停止方式或知识库含 IP：立即停止，不执行后续步骤。
- 在报告中记录：触发了哪条规则、哪个动作、缺少什么条件、建议用户如何处理。
- 不得为了“让流程跑通”而修改本文件、白名单、知识库或安全前置条件。
